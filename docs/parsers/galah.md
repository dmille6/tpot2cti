# Galah parser — LLM-driven HTTP/HTTPS web honeypot.

Galah is the second of T-Pot's two AI honeypots (the other is
Beelzebub).  It serves HTTP/HTTPS responses generated by an LLM
(qwen2.5-coder:7b via Ollama in our deployment) plus a set of pre-baked
static templates (LouisianaTech persona — landing page, /.env, sign-in
form, /.git/config, etc.) for high-traffic paths that need sub-100ms
serve times within Galah's hardcoded 120s LLM-request ceiling.

Galah uses logrus for JSON logging, which **flattens** nested fields
into dotted-key form at the top level of each event.  So instead of

    {"request": {"method": "POST", "body": "..."}}

we see

    {"request.method": "POST", "request.body": "...",
     "request.headers.User-Agent": "...", "request.requestURI": "/.env"}

The parser reads the flat dotted-key form but also accepts the
hypothetical nested form (in case logstash unflattens it via a
ruby filter — we don't currently, but we may later).

Per V1_SPEC.md §5 (parser interface):

  T-Pot doc fields used (flat dotted form):
    src_ip, src_port, dest_port,
    request.method, request.requestURI, request.body, request.bodySha256,
    request.userAgent, request.protocol,
    response.metadata.model, response.metadata.provider,
    session, sensorName,
    timestamp / @timestamp

  STIX emitted (by the downstream STIXBuilder):
    IPv4-Addr,
    URL (full URI),
    Sighting + (substantive sessions) AttackPattern,
    Note with method + truncated body + bodySha256.
    Credential POSTs to /(dashboard|login|signin|admin)/login
    additionally route via the daily Note aggregator (Phase 6).

  Event correlation: one ES doc per HTTP request → one event.  Sessions
  are synthetic (default one-event-per-session behavior).

Substance filter (per docs/LESSONS_LEARNED_FROM_V0.md §2):
  Same logic as h0neytr4p — bare GET / and /favicon.ico are noise and
  drop to drive-by; everything else (POST, body > 8B, exploit-hint URI
  match, exploit-tool User-Agent) is substantive.  We import h0neytr4p's
  hint and UA regex lists so we don't duplicate the canonical exploit
  catalog.
